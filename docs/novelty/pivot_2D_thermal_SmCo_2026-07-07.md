## 1. Вердикт «2D vs 3D»: это не отказ, а пере-ярусность

### 1.1. Что УЖЕ есть в 3D (не пропадает)

3D-ветка — **не «заготовка», а верифицированное ядро**: смешанная A-Coulomb система (Nédélec), BEM-экстерьер (V/K/W + квадратура Заутера–Шваба), симметричная связка Костабеля с решателем и калибровкой, нелинейный Picard (сталь+магнит) в открытой области, необратимый B(H,T)-демаг с коленом и картой риска, периодический сектор PMSM, когомологии; 3 аналитических эталона + MMS; 408 зелёных тестов.

### 1.2. Чего 3D-путь ещё ТРЕБОВАЛ БЫ до дизайн-инструмента

- сетки реальных геометрий (интеграция gmsh; сейчас только структурные генераторы);
- вращение ротора (sliding interface / remeshing — в 3D тяжело);
- масштаб: плотный BEM O(N²) → FMM/H-матрицы (большая отдельная работа);
- пост-процессинг (момент/EMF/потери) в 3D;
- тепловая задача в 3D;
- cuts для реальной топологии мотора.

Оценка: **многие месяцы** для одного разработчика, высокий риск. Тестовый прогон уже ~10 мин на игрушечных размерах.

### 1.3. Что переносится в 2D (инвентаризация по файлам)

| Слой | Переносимость | Комментарий |
|---|---|---|
| Материалы + физика демага (`SteelBHCurve`, `AnisotropicBHTMagnet`, C¹-кривая колена, `MagnetDemagPolicy`, risk-map) | **~95% дословно** | оперируют поячеечными массивами B/H и осью намагничивания — от размерности не зависят. **Это ядро новизны — оно сохраняется целиком** |
| Picard-драйверы (цикл, недорелаксация ω, критерии, история) | ~45–60% (архитектура) | сборка меняется, цикл и уроки сходимости (ω=0.5 при демаге) — те же |
| Методология тестов (MMS-структура, аналитические оракулы) | ~60% | сфера→цилиндр: намагниченный `H_in=−M/2`, проницаемый `H_in=2H₀/(μ_r+1)` |
| FEM-сборка | ~20% (паттерн) | Nédélec-тетры → **скалярный A_z на P1-треугольниках: проще**, седловая калибровка не нужна |
| BEM | ~30% (паттерн) | 1/(4πr) → log r; сингулярности слабее; логика адаптивности/классификации пар переносится |
| Сетки | переписать | TetraMesh → TriangleMesh (+ дальше gmsh для реальных сечений) |

Оценка нового кода: ~3.2–3.5 тыс. строк, **~4–6 недель до верифицированного 2D-ядра** с демагом в открытой области (паритет с текущей 3D-функциональностью).

### 1.4. Почему 2D — правильный ход ИМЕННО для новой темы

1. **Тепло становится ядром** — двусторонний Picard магнит↔T в 2D дешёвый; в 3D был бы «дорогим opt-in».
2. Радиальные машины (outrunner PMSM и ДП25) — классические 2D-объекты; отрасль (FEMM, Motor-CAD, Maxwell 2D) проектирует в 2D + поправки на торцевые эффекты.
3. Быстрый форвард ⇒ реальны sweeps по углу ротора, оптимизация, датасеты для суррогата («интеллектуальная» надстройка).
4. НТС-визуальность: сечения, линии потока, цветные карты риска демага и температуры — ровно то, что просил совет.
5. Уроки 3D (знаки, оракулы, ω-релаксация при отрицательной производной карты, методика закалки тестов) — уже оплачены и переносятся.

### 1.5. Судьба 3D-ветки — СОХРАНЯЕТСЯ как второй решатель (решение Sergey 2026-07-09)

**Не «заморозить и забыть», а «сохранить активным для последующей реактивации».** Конечная цель — **ДВА решателя (2D + 3D) в одном комплексе** с общим физическим ядром; 3D реактивируется и развивается ПОСЛЕ полной разработки + верификации + валидации 2D. До тех пор 3D:
- **не удаляется и не «гниёт»**: все 408 тестов 3D остаются в наборе и держатся зелёными — это регрессионный контракт (гарантия, что 3D можно включить в любой момент);
- **не развивается по фичам** (тепло/оптимизация/суррогат строятся сначала в 2D);
- служит: (а) верификационным полигоном методики (доказана в 3D на канонических задачах); (б) заделом второго решателя; (в) ответом оппоненту «а вне плоскости?».

**Ключевой инженерный вывод:** чтобы 3D действительно можно было «включить потом», а 95% переноса материализовались как ОБЩИЙ код, а не copy-paste, — нужно вынести размерно-независимое ядро в общий слой, который импортируют оба backend'а (см. §1.6). Иначе 2D и 3D разойдутся и реактивация 3D потребует переписывания.

### 1.6. Архитектура: общее физическое ядро + два геометрических backend'а

Это и инженерное решение, и **элемент новизны-носителя** (программный комплекс = единый физический движок с двумя backend'ами, а не два разных кода):

```
magcore/
  <ЯДРО, размерно-независимое — импортируют ОБА решателя>
    materials/  B(H)-сталь, B(H,T)-магнит, C¹-колено, кривые        (DIM-FREE ~95%)
    demag/      MagnetDemagPolicy, risk-map (работа с B/H по ячейке) (DIM-FREE)
    nonlinear/  Picard-драйвер, параметризованный CALLBACK'ом сборки  (PATTERN)
                assemble(nu, magnetization) -> (A, b); relaxation; история; критерии
    linalg/     решатель седловой/блок-системы, gauge-диагностика     (DIM-FREE)
    verify/     каркас MMS + аналитические оракулы (сфера↔цилиндр)     (методология)
  backends/
    fem3d/      текущий код: Nédélec-тетры, 3D BEM-экстерьер, tetra-mesh  [ЗАМОРОЖЕН, зелёный]
    fem2d/      новый: скалярный A_z / P1-треугольники, Kelvin-экстерьер [РАЗРАБОТКА]
```

Принцип: **Picard-петля, политика демага, материалы, линейная алгебра, методология тестов — пишутся ОДИН раз** и вызывают backend через узкий интерфейс сборки `assemble(nu, magnetization) -> (A, b)` и извлечения `B = curl A`. Тогда:
- тепловой модуль (2D-T), суррогат, оптимизация, добавленные в ядро, **автоматически станут доступны 3D** при его реактивации;
- регрессионный набор 3D продолжает исполнять общий код ⇒ рефакторинг ядра не может тихо сломать 3D;
- «комплекс с общим ядром и двумя backend'ами» — чистый нарратив общности (усиливает К2/К9).

**Цена:** первый шаг плана (2D-0) — аккуратно вынести размерно-независимые модули из текущего 3D-дерева в общий слой БЕЗ изменения поведения (регрессия 408 тестов = 0 diff). Риск черни — управляемый (это перемещение + параметризация драйвера callback'ом, не переписывание физики).

**Вердикт: принять решение научрука. Формулировка — не «отказ от 3D», а «2D — первый разрабатываемый решатель, 3D — сохранённый второй, оба на общем физическом ядре; 3D реактивируется после полной V&V 2D».**

## 2. Prior-art: что дал раунд-1 (верифицировано 3-0, первоисточники)

1. **FEM/BEM-связка = строго инфраструктура** (окончательно): Штутгарт (Kurz–Fetzer–Lehner–Rucker 1997 — слабая форма + нелинейное железо через M(B) fixed-point; актуатор в design-loop к 2009), Salgado–Selgas 2008 (симметричная BEM-FEM магнитостатика, сходимость Галёркина), TAILSIT/Kielhorn–Rüberg–Zechner 2016–2021 (движение без ремешинга, FMM, **секторная периодичность блок-циркулянтным BEM**). Picard+нелинейное железо+периодический сектор в связке — тоже занято.
2. **Ядро К1 ДЕРЖИТСЯ и в 2D**: у TAILSIT/Штутгарта магнит — фиксированная M в правой части, ноль вхождений demag/temperature/knee по полнотекстовому скану; встречный поиск не нашёл ни одной работы «необратимый демаг внутри BEM-экстерьерного решателя».
3. **Сам демаг — prior art**: Maxwell (модель Zhou et al., IEEE TMag 2012) — поэлементный curve-driven B(H,T), колено+recoil, история T-циклов; JMAG JAC120 — необратимая потеря 16% момента после цикла 60→140→60°C. Оба — **меш-усечённые** (balloon/бокс). ⇒ новизна не «модель колена», а **комбинация «колено+история+карта риска ВНУТРИ открытого решателя» + связка с теплом**.
4. **FEMM**: открытая граница = IABC/Kelvin, BEM нет; необратимого демага нет. ⚠ **Важная поправка формулировки**: Kelvin-трансформация в 2D **точна** ⇒ нельзя говорить «ни у кого нет точной открытой границы в 2D»; правильная формулировка — «ни у кого нет необратимого B(H,T)-демага внутри решателя с открытой границей».
5. **ELCUT/QuickField (РФ)**: ПМ = кусочно-постоянная Hc (эквивалент поверхностных токов), «hysteresis curve задать нельзя» (вендор), T-зависимости магнита нет, открытой границы нет (Dirichlet-бокс). **Домашний аргумент усиливается конкретным фактом.**

### 2.1. Нужен ли гибридный (FEM/BEM) решатель в 2D? — РЕКОМЕНДАЦИЯ: НЕТ

После снятия «открытой области» из новизны (§3.0) у BEM в 2D **не остаётся ни одного оправдания как элемента вклада** — остаётся чистая инженерия «чем замкнуть бесконечную область». Разбор вариантов экстерьера для 2D-магнитостатики:

| Способ | Точность откр. границы | Стоимость реализации | Совместимость с нелин.+магнит+тепло | Прайор-арт-статус |
|---|---|---|---|---|
| **Kelvin-трансформация** (инверсия во 2-й диск) | **ТОЧНАЯ в 2D** | низкая (чистый FEM, +1 область) | полная (экстерьер = воздух, линеен; нелинейка/магниты — во внутренней области) | стандарт (FEMM) |
| Усечение / balloon / IABC | приближённая | низкая | полная | стандарт (Maxwell 2D, Motor-CAD) |
| **Гибрид FEM/BEM** (наш 3D-подход) | точная | **высокая** (log-ядра, сингул. квадратура, знаки связки) | полная | инфраструктура (Штутгарт/TAILSIT) |

**Почему гибрид в 2D не нужен:**
1. **Нулевой выигрыш точности**: в 2D Kelvin-трансформация даёт ТОЧНОЕ решение неограниченной задачи БЕСПЛАТНО (чистый FEM). Главное преимущество BEM (точный экстерьер) в 2D нейтрализовано.
2. **Нет новизны**: открытую область больше не заявляем ⇒ дорогой BEM оплачивается только инженерно, а инженерно Kelvin дешевле и тоже точен.
3. **Физика темы не в экстерьере**: демаг и тепло живут ВНУТРИ магнита/железа; поле мотора в основном заперто ярмом. Отрасль (FEMM/Maxwell 2D/Motor-CAD) проектирует моторы усечением/Kelvin — это принято и не оспаривается.
4. **Экономия ~1–2 недель** самого ошибкоопасного кода (сингулярная квадратура, знаки связки) → в тепловое ядро (К6′) и суррогат.
5. **Общее ядро не страдает**: backend'ы ЗАКОННО различаются трактовкой экстерьера (2D — Kelvin, 3D — BEM), разделяя физическое ядро (материалы/демаг/Picard/тепло). «Комплекс = единый физический движок + два backend'а» остаётся в силе; нарратив общности не про одинаковую математику границы.

**РЕШЕНИЕ (Sergey 2026-07-09): вариант 1 — Kelvin-трансформация**, гибрид FEM/BEM в 2D НЕ строим. Экстерьер = Kelvin (точно, чистый FEM, «как в FEMM» ⇒ защитимо), при желании усечение для быстрых прогонов. Аналитический цилиндр + MMS + (опц.) FEMM = независимые оракулы. **3D-гибрid BEM сохраняется как есть** (заморожен, зелёный) — готовый актив второго решателя, переписывать/выбрасывать не нужно; в 2D не воспроизводим.

### 2.1a. PINN в 2D-ядре? — НЕТ (ядро остаётся FEM); разбор Sergey 2026-07-09

Отдельно рассмотрен вопрос «а если ядром 2D сделать PINN». Ответ — **нет, forward-решатель остаётся FEM**; пивот только усиливает этот вывод (полный разбор `docs/ml/pinn_integration_analysis.md`, обновлён под пивот):
- **колено + необратимость + история нагружения = worst case для PINN** (гладкий `tanh`-анзац не представляет излом; нет естественной «памяти состояния» по точкам) — а это ТЕПЕРЬ ядро новизны (К6′);
- разрывы на интерфейсах воздух/магнит/сталь и `r^α`-сингулярности на кромках = зоны демаг-риска, гладкая сеть их не ловит;
- связка с теплом (двусторонний Picard + runaway) требует тысяч устойчивых ДЕТЕРМИНИРОВАННЫХ прогонов — PINN медленный/стохастичный/ручная настройка на кейс;
- нет гарантий сходимости ⇒ прямое нарушение стоячего принципа «качество ≥ скорость, MMS/аналитические оракулы»;
- чувствительные QoI (cogging, поточечный демаг-запас) раздувают ошибку поля PINN;
- дрейф в вычматематику/ML (риск для 2.4.2) + PINN-PMSM уже опубликован (не ново).

**Наследие PINN живёт НАД верифицированным FEM, не вместо него:** (A) суррогат с physics-informed регуляризацией / PI-нейрооператор + conformal prediction = содержание «интеллектуальной системы» (К5, фаза 2D-F; точность и сертификация от FEM+CP, не от невязки сети); (C) warm-start Picard; (E) PINN-forward как baseline-для-сравнения (упреждает «почему не PINN» своими данными). Экстерьер: PINN как открытая граница строго хуже Kelvin ⇒ решения не меняет.

### 2.2. Раунд-2 (верифицировано по первоисточникам) + инлайн-добор РФ

**(а) Магнито-тепловая связка с демагом — К6 ОЖИВАЕТ как ядро №2, но ТОЛЬКО в суженной формулировке.**
- ЗАНЯТО: двусторонняя EM↔тепло итерация per se — стандартная практика 2021–2026 (Extrica 2022 Maxwell 2D+Workbench, IEEE 2021, WEVJ 2026). **Motor-CAD/Sheffield (Energies 2023 16(1):131, соавторы — вендор Motor Design Ltd; verified 3-0 по полному тексту)**: температура передаётся В необратимую демаг-модель внутри итерации до сходимости ΔT, публикуются карты остаточной Br. **НО**: тепло = LPTN (сосредоточенная сеть, не полевое), только steady-state (каскад явно исключён допущением), EM = ограниченный FE (BEM/open-boundary — 0 вхождений), фиксированные топологии, готовый коммерческий инструмент.
- WEVJ 2026 (EV-цикл): демаг проверяется ПОСТ-ХОК по колену и вносится как ручной сценарий — не самосогласованный.
- Maxwell 2024 R2: необратимый демаг с историей T-циклов есть (модель Zhou 2012), но документированный воркфлоу секвенциальный (thermal modifiers); участие необратимой knee-модели в двустороннем Maxwell↔Icepak цикле нигде не заявлено.
- Gangl/Krenn (RICAM, arXiv:2404.12188): демаг как активное точечное ограничение в топологической оптимизации 2D PMSM — ЗАНЯТО, но изотермически (N42@100°C, без B(H,T), без необратимости/истории); их же follow-up 2025 с теплом (2507.14759) — ЛИНЕЙНЫЙ магнит; необратимость сами откладывают в Outlook. ⚠ Окно сужается: 3 препринта группы за 2024–2025 ⇒ публиковать ядро №2 в 2026–2027.
- **БЕЛАЯ СВЯЗКА (= формулировка К6′, БЕЗ упоминания границы)**: полевой (2D FEM) связанный магнитотепловой расчёт, где необратимый B(H,T)-демаг с коленом и историей живёт ВНУТРИ самосогласованной итерации, с транзиентным каскадом thermal runaway и риск-картой как активным ограничением в петле проектирования. Каждый элемент по отдельности имеет соседей (называть явно: Sheffield, WEVJ, Gangl, Kern, Maxwell) — связка целиком не занята никем. Экстерьер (как замкнуть бесконечную область) в формулировку НЕ входит.

**(б) SmCo — модель бела, данные для валидации готовы, RF-производство живо.**
- Ближайший prior-art материальной модели: **Kern/Leuning/Hameyer (RWTH, AIP Adv 13:025105, 2023)** — полуфизическая B(H,T)-модель колена, но параметризована ТОЛЬКО на NdFeB (20–120°C). PDF уже в корне репо (`rwth953198.pdf`). Solver-embedded модель Sm2Co17 — НЕ НАЙДЕНА = белая ниша.
- **NASA TP-3119 (Niedra & Overton, 1991)**: экспериментальные карты безопасной работы Sm2Co17 при 23–300°C — выше 200°C колено входит во 2-й квадрант; лучший образец теряет запас при 280°C (ΔB=0.9Br), худший при 240°C; при 250°C ни один не держит ΔB=Br. **Готовые данные для параметризации и валидации нашей curve-driven модели.**
- Температурный аргумент (verified 2-1 с оговоркой): стандартные Sm2Co17 ≈300–350°C против ≈200–230°C у лучших EH/AH NdFeB; «до 500°C» цитировать НЕЛЬЗЯ (только UHT-марки с пониженным (BH)max).
- **РФ-производство / доступ к SmCo (уточнение Sergey 2026-07-09): ВОПРОС СНЯТ И ОБРАЩЁН В АКТИВ — «магниты производим сами».** Это перестаёт быть риском (не нужны Wayback-снимки/вендор-datasheet для доказательства доступности) и становится **сильнейшим активом достоверности и внедрения**:
  - **валидация первого рода**: собственные измеренные кривые B(H,T) и необратимой потери Sm2Co17 → валидация решателя против магнитов СОБСТВЕННОГО производства (сильнее, чем NASA-1991/вендор-datasheet). Прямо закрывает требование «достоверность результатов» диссертации;
  - **акт внедрения** практически обеспечен (реальное производство + реальное изделие) — ключ для защиты ВАК;
  - **импортозамещение** переформулируется с «в РФ производят SmCo» (доказывать) на «предприятие производит SmCo и получает под него инструмент проектирования» (факт).
  - NASA TP-3119 и ГОСТ 21559-76 (КС25ДЦ-150…240: Br 0,90–1,10 Тл, HcB 690–780 кА/м, (BH)max 150–240 кДж/м³) остаются как ПУБЛИЧНЫЕ реперы для сопоставления/цитирования, но количественная параметризация и валидация идут по СВОИМ данным. Против N42SH (Br≈1,3 Тл) — проектный trade-off «Br vs тепловая стойкость» = предмет методики.

**(в) «Интеллектуальная система» и сертифицированный суррогат.**
- CP-в-дизайн-петле мотора — БЕЛО: флагманская CP-для-суррогатов работа (arXiv 2408.09881) — PDE/токамаки/погода, машин нет, CP на inference; CREATOR (DFG CRC, Bosch, ~20 M€) занимает NN-суррогаты+UQ в дизайне машин (GPR/NN, порт-гамильтоновы NN), но conformal prediction не упоминает; июнь-2026 препринт (2606.09923) уже застолбил «первое применение split-CP к нейрооператорам» (не моторы). Окно — месяцы.
- Термин «интеллектуальная система проектирования» в РФ живёт в культуре САПР-специальности (диссертации типа «методология автоматизированного проектирования ПМ-машин…», 05.13.12) ⇒ **риск возражения «это САПР/2.3.7, а не 2.4.2»** при вынесении в голову названия. Рекомендация: интеллектуальность — как содержание задач (сертифицированный суррогат в петле), не как головное существительное темы.

**(г) РФ-диссертации-конкуренты (инлайн, medium confidence).** Прямой связки «тепло + необратимый демаг + открытая граница + программный комплекс + БПЛА» не найдено. Соседи для цитирования/отстройки: безжелезные дисковые Хальбах-машины для ЛА (dissercat, свежая), тепловые поля/мониторинг асинхронников (старые 05.09.01), методология САПР ПМ-машин биотехнических приводов (05.13.12), приводы БПЛА МАИ/МЭИ (управленческие). Ступаков (НГТУ 2016) остаётся ближайшим соседом по решателю. Caveat: полнотекстовый eLibrary/НЭБ-добор вручную перед защитой (стоячий пункт с июня).

## 3. Пересборка новизны (по итогам обоих раундов)

### 3.0. РЕШЕНИЕ Sergey/научрук 2026-07-09: «открытая область» УХОДИТ из новизны полностью

Причина: BEM по определению строится на открытой (неограниченной) области — это его принцип, а не наш вклад; заявлять «открытую границу / открытую область» как отличительный признак = притягивать за уши, научрук не одобряет. ⇒ **ни одна формулировка новизны и ни один пункт положений не оперирует «открытой областью / открытой границей».** Экстерьер решателя — чисто инженерный выбор (см. §2.1, вопрос гибрида), не элемент новизны.

**Следствие (честное):** «необратимый демаг ВНУТРИ решателя» сам по себе НЕ отличает нас от Maxwell/JMAG (они ровно это и делают). Отличие держится ТОЛЬКО на **полевой самосогласованной магнитотепловой связке + необратимость-в-итерации + runaway + риск-в-петле-проектирования** (бывш. К6′) и на носителях (SmCo своими магнитами + отеч. комплекс). ⇒ прежнее «двухъядерное» (К1′+К6′) схлопывается в **ОДНО ядро (К6′) с материаловым и комплексным носителями**; К1′ как отдельная новизна снимается (был завязан на открытую границу).

| Было (матрица 2026-06-16) | Становится | Статус |
|---|---|---|
| К1: необратимый B(H,T)+колено+risk-map в открытом FEM/BEM | **СНЯТ как отдельная новизна** (держался на открытой границе; демаг-в-решателе есть у Maxwell/JMAG) → поглощается К6′ | демотирован |
| К6: монолит демаг-тепло (понижен: «дорого соло») | **К6′ = ЕДИНОЕ ЯДРО**: полевой (2D FEM) связанный магнитотепловой расчёт, где необратимый curve-driven B(H,T)-демаг (колено + история + risk-map) вычисляется САМОСОГЛАСОВАННО внутри магнитотепловой итерации, с транзиентным каскадом thermal runaway и демаг-риском как активным ограничением в петле проектирования. Нигде — ни в одном пункте — не фигурирует «открытая область».

```
2D-0  РЕФАКТОР: вынести размерно-независимое ядро (materials/demag/nonlinear-
      драйвер/linalg/verify) в общий слой; параметризовать Picard callback'ом

2D-A  Backend fem2d, ядро FEM: TriangleMesh + P1 A_z + ток/намагнич. RHS + MMS  [~1-2 нед]
2D-B  Экстерьер: Kelvin-трансформация (инверсия во 2-й диск, чистый FEM, точно)
      + оракулы (намагнич./прониц. цилиндр, MMS, опц. FEMM-кросс)               [~3-5 дней]
2D-C  Нелинейка+демаг: подключить общий Picard + сталь + MagnetDemagPolicy
      (импорт из ядра, НЕ переписывание) + knee/risk-map + периодический сектор  [~1 нед]
2D-T  ТЕПЛО (ядро №2): P1-термо на той же сетке, потери (медь+Bertotti),

      кейс NdFeB vs SmCo (свои измеренные кривые)                               [~2-3 нед]
2D-V  ВАЛИДАЦИЯ: сопоставление с собственными измерениями своих магнитов
      + (опц.) FEMM/аналитика как внешний репер                                 [параллельно]
2D-P  Пост: момент (Maxwell stress/Arkkio), EMF, потери, sweep по углу
2D-D  Параметризация outrunner + ДП25-кейс (общность)
2D-E  Adjoint (2D, сквозь регуляризованное колено — узкая формулировка)

3D+   РЕАКТИВАЦИЯ 3D (backend fem3d) ПОСЛЕ полной V&V 2D: тепло/суррогат/оптим.
```
