## 0. Что уже есть (фундамент, переиспользуется)

Верифицированное 2D-ядро `magcore/fem2d` (27 тестов, под оракулами):
- скалярный `A_z` на P1-треугольниках, нелинейный Picard (сталь), токовый источник,
  источник магнита; общий размерно-независимый цикл `run_picard_fixed_point`;
- модель магнита `B(H,T)` (колено + recoil + `effective_Br` = количественная потеря),
  `temperature_limit`, risk-map; сталь `B(H)`;
- Kelvin-экстерьер (для открытых форм), тепловой FEM + анализ разгона (для S2).

**Что НЕ так с текущим пилотом** (по итогам разбора): статический тепловой solve → T
= физически неверный способ получить температуру; `applied_B0` вручную вместо поля из
обмотки; бинарный счётчик «за коленом» вместо количественной потери. Всё это заменяется
ниже. Визуализация пилота (`pilot/viz.py`) сохраняется под будущий интерфейс.

### Три сценария (согласованы)
- **S1** — статика, 20 °C, поле только от обмоток (реакция якоря). Демаг чисто магнитный.
- **S3** — статика, температура **задана** (промежуточный). «Магнит при T — цел ли под полем».
- **S2** — динамика: вращение + потери из полей + транзиентный нагрев → установившаяся T
  и связка магнит↔тепло (ядро новизны К6′). Крупный этап поверх статического решателя,
  переиспользующий его на каждом шаге по времени (см. Часть III).

Обоснование кинетикой: переключение доменов полем и отклик на *заданную* T — мгновенны;
медленна только тепловая диффузия. ⇒ S1 и S3 законно статические; вычисление T — только S2.

## ЧАСТЬ I. Полная модель статической задачи (до интерфейса)

Каждая фаза: **цель · вход · работа · РЕЗУЛЬТАТ · проверка(оракул)**. Оценки — грубые.

### P1. Параметрическая геометрия сечения машины  [~2 нед]
- **Цель:** реальное сечение (не диск-в-коробке): магнит(ы) + сталь + пазы + обмоточные
  области + зазор, с тегами областей.
- **Вход:** тип машины (outrunner SPM / ДП25) + размеры (числа полюсов/пазов, диаметры,
  толщина магнита/ярма, зазор, геометрия паза).
- **Работа:** параметрический мешер (свой 2D-генератор — как 3D `build_annular_sector`, но
  плоский; gmsh опционально). Секторная периодичность (один полюс) или полное сечение.
  Границу берём по внешней стали (поток заперт ярмом ⇒ ограниченная область, Kelvin не
  обязателен внутри железа).
- **РЕЗУЛЬТАТ:** `TriangleMesh` реальной машины + маски областей (магнит/сталь/паз/воздух),
  для outrunner PMSM и ДП25.
- **Проверка:** площади областей, ширина зазора, конформность разрезов периодичности,
  визуальный контроль сетки.

### P2. Материалы = реальные данные  [~0.5 нед, параллельно P1]
- **Цель:** уйти от «представительных» чисел к измеренным.
- **Вход:** ваши измеренные кривые магнита `B(H,T)` (вы производите магниты) + сталь `B(H)`
  (M270 или марка объекта).
- **Работа:** загрузка/фитинг кривых в существующую модель (`demag_curve_from_datasheet`
  уже принимает datasheet-параметры); реальные температурные коэффициенты.
- **РЕЗУЛЬТАТ:** материалы объекта с достоверными кривыми; корректный `temperature_limit`.
- **Проверка:** сверка построенной кривой с исходными измерениями/datasheet (как ранее с Excel).

### P3. Обмотка и ток якоря (поле реакции — из параметров катушки)  [ЯДРО ГОТОВО 2026-07-14]
- **Цель:** поле якоря вычисляется из обмотки, а не задаётся числом.
- **Вход:** параметры обмотки (раскладка фаз по пазам — `star_of_slots_layout`, готова P1;
  число проводников в пазу N; фазные токи); worst-case **по-простому**: амплитуда тока +
  d-ось (`worst_case_d_axis_currents`).
- **Работа:** ✅ `machines/winding.py` (разметка фаз/знак по пазам, готово P1) +
  `machines/excitation.py`: `phase_currents(i_peak, γ)` (сбаланс. 3 фазы) →
  `slot_current_density(geom, layout, I_phase, N)` = поячеечный `J_z` с точными А·витками
  на паз → `assemble_current_rhs_piecewise` (кусочно-пост. источник, точен для P1).
- **РЕЗУЛЬТАТ:** ✅ токовый источник машины из параметров обмотки; worst-case режим (d-ось).
- **Проверка:** ✅ ∫_s J_z dA = sign·N·I_phase (оракул А·витков); баланс 3 фаз (сумма=0,
  амплитуда 1.5·i_peak по Кларку); суммарные А·витки=0 при сбаланс. обмотке; разбиение
  единицы Σf=∫J; совпадение с квадратурным ассемблером на константе. (7 тестов, зелёные.)
- **ОТКРЫТО → P4:** ТОЧНЫЙ худший электрический угол γ (и положение ротора) ищется свипом
  в P4 по минимуму H_par в магните — нужно решённое поле; поле «пустой» обмотки против
  аналитики (МДС/зазор) — тоже удобнее проверить уже в связке P4.

### P4. Полный связанный статический решатель в реальной геометрии  [ВЫПОЛНЕН 2026-07-14]
- **Цель:** свести всё: магнит (с демагом) + нелинейная сталь + ток обмотки, для S1 и S3.
- **Вход:** геометрия (P1) + материалы (representative как ДАННЫЕ) + ток (P3) + T (20° S1 /
  заданная S3).
- **Работа:** ✅ `machines/static_solver.py::solve_machine_static` — поячеечная `ν`
  (ОТНОСИТЕЛЬНАЯ 1/μ_r: воздух=1, магнит=1/μ_rec, сталь=μ₀·ν_chord(|B|)) + источники
  (магнит `ν·Br_eff·e` через `MagnetDemagPolicy` с ПОЯЧЕЕЧНОЙ радиальной осью, ток из P3 =
  μ₀·J) → общий Picard на сетке машины. ГУ A_z=0 на границе (поток заперт в ярмах).
  `worst_case_gamma_sweep` = истинный worst-case перебором эл. угла γ.
- **РЕЗУЛЬТАТ:** ✅ поле `B` во всей машине; рабочая точка/маржа/потеря каждой ячейки
  магнита (risk-map) при токе и T. Зазорное |B|~0.58 T (среднее), сталь до ~1.9 T.
- **Проверка:** ✅ 8 оракулов: сходимость S1/S3; зазорное |B| физично; **доминирующая
  угловая гармоника = p** (полярности верны); ток=0→только магнит, демаг-маржа падает от
  d-тока и от нагрева (монотонно), заход за колено при T (n_demag>0, loss>0); свип берёт
  минимум; обобщение оси. Все 3D/box demag-тесты зелёные (single-axis сохранён).
- **ⓘ Уроки:** (1) убраны orphan-узлы gmsh (вырожденная K); (2) хордовый Picard по
  насыщающейся стали склонен к предельному циклу → relaxation=0.1 (монотонно, ~85-90 итер);
  на тонких сетках/сильном приводе — меньше релаксация или Ньютон через ν_d (задел).

### P5. Количественная необратимая потеря (по вашей модели)  [ВЫПОЛНЕН 2026-07-14]
- **Цель:** не «за коленом/нет», а **сколько** потеряно.
- **Вход:** результат P4 (рабочие точки при worst-case) + модель `effective_Br`.
- **Работа:** ✅ `machines/loss.py`. `magnet_loss_aggregate` — агрегаты по магниту (доля
  площади за коленом, средняя/макс относит. потеря `Br`, потерянный поток источника).
  `phase_flux_linkage` — λ фаз из `A_z`. **`evaluate_demag_impact`** (машинный итог): под
  worst-case берём СОШЕДШЕЕСЯ поле → замораживаем `Br_eff` (линия возврата) → сравниваем λ
  ХХ номинал vs замороженный при той же T ⇒ **относит. падение λ = падение ЭДС/моментной
  постоянной** (изолирует необратимую потерю; обратимое T-падение сокращается).
- **РЕЗУЛЬТАТ:** ✅ карта % потери `Br` (risk-map, P4) + агрегат «сколько теряет машина» в
  ЭДС/моменте. Пример N42SH при T=140°: demag_area 9.3%, mean_loss 0.27%, **λ-drop 1.25%**.
- **Проверка:** ✅ 6 оракулов: холодный без потери (drop≈0); горячий — потеря>0, монотонно
  растёт с T; λ-drop одного порядка со средней потерей Br (согласованность); упорядоченность
  агрегатов; λ ХХ сбалансирована. **⚠ Урок:** `H_par` для заморозки — из СОШЕДШЕГОСЯ поля,
  НЕ из `track_worst_point` (latching по итерациям Picard ловит численные выбросы → давал
  λ-drop 17.6% при mean_loss 0.4%; после фикса 1.25%). Глубокий демаг (T=170) не сходится =
  честная неустойчивость (флаг `load_converged`).

### P6. Пост-процессинг (ЧИСТО СТАТИЧЕСКИЙ)  [~1.5 нед]
- **Цель:** инженерные величины из статического поля, до и после демага.
- **Вход:** поле из P4 (номинал и после демага из P5).
- **Работа:** момент (Maxwell stress / Arkkio по зазору), потокосцепление и ЭДС-постоянная
  (`phase_flux_linkage` готова в P5). Аддитивно в `magcore` с оракулами.
- **РЕЗУЛЬТАТ:** момент, ЭДС/потокосцепление, cogging (опц.), и их снижение из-за демага.
- **Проверка:** согласованность Arkkio (площадь) ≈ Maxwell-stress (линия); момент линеен по
  току и меняет знак; cogging мал относительно нагруженного момента.
- **⚠ ПОТЕРИ И НАГРЕВ — НЕ ЗДЕСЬ (решение Sergey 2026-07-14):** нагрев по природе
  ТРАНЗИЕНТЕН (накопление тепла = время), в СТАТИКЕ его нет. Потери меди `ρ_cu(T)·I²R` +
  железа — это ИСТОЧНИКИ ТЕПЛА в ДИНАМИЧЕСКОМ модуле (S2 / Часть III), где есть время: там
  ток→потери→тепловое поле→T(t)→демаг. В статике T — чистый ВХОД (S1:20°, S3:задана).

### P7. Согласованная МОДЕЛЬ ЗАДАЧИ (схема входных данных)  [~1 нед]
- **Цель:** единая, проверяемая структура всего входа — «полностью согласованная модель».
- **Вход:** всё из P1–P3 (геометрия, материалы, обмотка, режим: ток, положение, T, сценарий).
- **Работа:** структура данных задачи + валидация (полнота, диапазоны, согласованность
  размеров), один вызов «модель → полный расчёт (P4–P6)».
- **РЕЗУЛЬТАТ:** «модель задачи» — всё необходимое для полного расчёта в одном месте, с
  проверкой корректности; расчёт запускается одним вызовом.
- **Проверка:** негативные тесты (неполный/несогласованный вход отвергается); сквозной
  прогон S1 и S3 на outrunner PMSM и ДП25.

- [ ] P2 — реальные материалы (измеренные кривые магнита + сталь)

**Результат гейта:** полностью согласованная модель задачи + полный расчёт + пост-проц.

## ЧАСТЬ II. Интерфейс  [~2–3 нед]

- **Цель:** пользователь сам задаёт модель задачи, запускает, проверяет расчёты руками.
- **Работа:** сначала конфиг/CLI по стабильной схеме P7 (переиспользовать `pilot/viz.py`);
  затем GUI/веб (`webapp/`), если нужно. Ввод: геометрия+материалы+обмотка+режим; вывод:
  поля, карта % потери, момент/ЭДС до/после, сравнение материалов (NdFeB vs SmCo).
- **РЕЗУЛЬТАТ:** рабочий инструмент проверки реального мотора (outrunner PMSM / ДП25).
- **Проверка:** оракулы рядом с результатом (аналитические реперы) для доверия.

## ЧАСТЬ III. Динамический тепловой модуль (S2) — ядро новизны К6′  [крупный этап]

> Полная магнитотепловая связка + необратимость + разгон — **ядро новизны диссертации**.
> Строится поверх статического решателя P4. По решению Sergey (2026-07-14) — **перед
> оптимизацией** (оптимизировать теплонагруженный мотор естественнее на полном форварде).

- **Цель:** вычислить, до какой T греется машина и как демаг развивается во времени.
- **Работа:** транзиентный тепловой FEM (есть стационарный, нужен по времени) + потери из
  полей (**медь `ρ_cu(T)·I²R` — джоулев нагрев обмотки током**, вихревые/железо, считаются из
  `B` и токов — уходим от заданного `heat_load`; медь — доминирующий источник для БПЛА) +
  вращение ротора (последовательность положений) + связка магнит↔T с защёлкиванием
  необратимого состояния по худшей совместной точке `(T_max, H_min)` (уточнение из разбора)
  + сценарий теплового разгона (есть линеаризованный порог `s_crit`).
- **РЕЗУЛЬТАТ:** установившаяся T, эволюция демага во времени, демонстрация разгона
  NdFeB vs SmCo; S2 доступен в интерфейсе как третий режим (расширяет UI из Части II).
- **Проверка:** энергобаланс; сверка стационара с аналитикой; порог разгона.

## ЧАСТЬ IV. Оптимизация  [~4–6 нед]

- **Цель:** автоматический подбор геометрии/обмотки/материала под требования — уже на
  **полном форварде** (статика S1/S3 + динамика/тепло S2).
- **Работа:** параметризация + целевые (момент/масса, удельные, демаг-запас, тепловой
  запас) + ограничения (демаг-потеря ≤ порог, момент ≥ треб., температура ≤ предел);
  оптимизатор (градиентный через **adjoint** — новизна К4, и/или **суррогат + conformal
  prediction** — новизна К5).
- **РЕЗУЛЬТАТ:** оптимальные конструкции под сценарии; сертифицированные запасы (интеллект.
  система).
- **Проверка:** воспроизведение известных трендов; сходимость; сертификация CP.
